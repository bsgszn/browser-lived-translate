## 一、一句话设计

**让 Whisper 决定「句子在哪结束」,让静音决定「那句到底说完了没」,
让排期决定「实在等不及就按 Whisper 的边界硬采纳」。VAD 不参与切句。**

## 三、链路

```
① 推进点 nextStart = 最后一个被采纳句子的 end(采样数,绝对位置)
② 取音频:takeRange(nextStart, nextStart + W*16000)  ← 连续原始 PCM,禁止拼接
   · 首批 W = 6 秒
   · 之后 W = 尾巴 + 5 秒
   · 如果取到的不够 W(还没采到那么多)→ 等下一帧,不送
③ POST /audio/transcriptions,response_format=verbose_json → segments[]
④ 逐个判(按 start 升序,只判「从 nextStart 起连续能被采纳的前缀」):
   · 该段 end 之后 200~300ms 内是否有静音?
     · 有   → 采纳,上屏,nextStart = end;继续判下一段
     · 没有 → 不采纳;nextStart = 该段 start;跳出,等下一批
⑤ 兜底:若本批一段都没采纳,且「从 nextStart 起已积压 > 单句上限(6 秒)」
   或「会超字幕排期」→ 强制采纳 Whisper 最后一个 segment 的 end
   ⚠️ 不用 VAD 找切点
⑥ VAD 只提供「某时刻是否静音」,不参与切句
```

## 四、关键实现点

### 4.1 音频取用 —— 现成的

- `lib/asr/vad.js:2251` `takeRange(absStart, absEnd)` —— 取绝对采样区间 ✓
- `baseOffset` / `totalSamples` —— 音频缓冲的绝对边界(`vad.js:1780-1781`)
- `carryStartFor()`(`vad.js:1375`)—— 已经处理「不能早于 baseOffset」,可参考
- ⚠️ **必须用 `takeRange` 从原始 PCM 连续取**,禁止把 VAD 切出来的碎片拼起来

### 4.2 静音确认选什么 —— **建议用现有 VAD 概率**

理由:
- 项目已有 `speechProb()`(Silero VAD)且已标定(阈值 0.5、640 窗、归一化支路)
- 与「切句」用的信号同源 → 不会出现两套标准互相矛盾
- 原始 RMS 不行:`HUMAN_LEVEL_RMS` 那一路今天已经证明「门槛够不着」(`0.03` vs 实测 `0.012`)

**判据**:`end` 之后 250ms 内,若 VAD 概率 **连续 ≥ 5 帧 < 0.5**(640 窗 = 40ms/帧,即 200ms 静音)
→ 认为「确实说完了」。

**阈值依据**:`softEndTick` 那套已经验证过「200~250ms 静音足够确认句尾」;
而 `vadMinSilenceMs 600` 是**猜**句尾时的值,现在位置已由 Whisper 给出,不需要那么长。

### 4.3 feature flag

```
asr.whisperChunked.whisperSegments: false   ← 默认关
```
- 默认关:未验证前不许改变现有行为
- 闭环里显式打开做 A/B
- 旧路一个字不改(`flushSpeech` / `softEndNeed` / `softEndTick` / `gate`)全部保留

### 4.4 延迟

```
首批:6 秒音频 + 一次往返(3~5 秒)+ 确认 0.25 秒 ≈ 10 秒
之后:6 秒音频 + 往返 ≈ 10 秒
```
- ⚠️ 比现在的 7.1 秒**多 3 秒**
- 设置页/说明要写清;闭环里 `目标延迟` 要相应提到 10 秒
