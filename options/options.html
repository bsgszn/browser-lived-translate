0 · 速度 / 准确度

「字幕出现得快」和「译文稳不跳」在实时翻译里基本是一对取舍。选一个预设就行， 下面各项会自动跟着变；手动改过任意一项就会显示成「自定义」。

说话人长时间不停顿时，识别服务可能一直不给「最终结果」，字幕会无限长、也拿不到干净译文。 「强制断句上限」就是这种时候的兜底，默认 10 秒。

翻译时机是固定的，没有旋钮：字幕该上屏的时刻往前推 0.7 秒开始翻译， 翻完先等着、到点才上屏。剩下的时间都在等后文。
如果实测翻译比 0.7 秒慢，会自动提前开始 —— 否则字幕必然迟到。 当前用的窗口和实测翻译耗时都显示在播放页底部。

1 · 语音识别（ASR）

把标签页里的声音转成文字。流式服务延迟最低（约 0.3–1 秒），分片模式延迟高但可以完全本地跑。

断句仍然在浏览器里做 —— 和「本地 VAD」用的是同一套 Silero VAD 引擎， 所以下面那块 VAD 的「语速档位」和几个旋钮对它一样有效（那些旋钮是调切句的， 不是调文本来源的）。

⚠️ 它不是流式：一句话说完才发给阿里云，比流式多一句的延迟 —— 延迟画面模式能盖住这个差距。浏览器里做不了流式，因为 DashScope 的流式接口要求把 API Key 放在 WebSocket 握手请求头里，而浏览器的 new WebSocket() 设不了请求头。

⚠️ 这个后端没有 Whisper 那种 no_speech_prob 置信度闸门 （阿里云不返回这个字段），所以只剩「空文本」和「幻听套话清单」两道闸门。

上面那个上限是按时间切的：切点落在"到上限时正在说的那个音"上，可能切在词中间，两边都缺字。 打开这一项之后，到上限时会回头看最近约 1.5 秒，找到一次换气就把切点挪过去 （8 秒的一口气会从 5.0 + 3.0 变成 4.5 + 3.5）。 找不到换气就完全和从前一样，所以关掉它只是"回到从前"，不是修正什么。
开启后，实际每段长度会落在 （上限 − 窗口）~ 上限 之间 —— 比如上限设 8 秒，实际就是 6.5~8 秒，不会把你设的值改小很多。

地址沿用下面「本地 Whisper 服务」那一栏 —— 和识别校正共用同一个服务，所以不用重复填。

文本来自阿里云百炼 —— API Key、端点、模型名、提示词、热词都在上面 「阿里云百炼」那一栏里填，这里只管怎么切句。

音源本身不好（差麦克风 / 说话快）怎么办 —— 见下面「自动增益档位」那一栏； 它对所有识别服务都生效，所以不放在这个面板里。

识别校正（流式定时间轴 + 本地模型定文本）

分工是固定的：流式识别的时间戳决定字幕什么时候上屏（这条不动）， 本地模型重新识别一遍决定字幕写什么。所以重识别失败、超时、或者服务没起， 都不会影响字幕的时序，只是没拿到那份加成。

用哪个地址：选「本地 Whisper」时用的是上面「本地 Whisper 服务」那一栏的地址， 跟当前选的是哪家流式识别无关 —— 即使流式用 Deepgram，本地地址也照样在那里填。

⚠️ 「自动」的含义容易误会：它是「跟着流式识别走」—— 流式选了 Deepgram，自动就等于用 Deepgram 非流式再识别一遍，不是本地 Whisper。
想让本地模型定文本（流式 Deepgram 定时间轴），必须显式选「本地 Whisper」。

⚠️ 「重识别提示词」为什么建议留空：实测 prompt 更容易把 Whisper 带偏，而不是帮它听准。 同一段真实日语：
　不加 → 「そうなんだよね / ティールで一瞬で流れたりするからね / あれピンクと黒の髪の毛の色はあれひなのじゃん」全对
　加日文相关词 → 丢掉第一句，还把「ひなの」听成「ひなうの」
　加一堵英文术语 → 严重损坏（旧版就是把翻译术语表拼进来，正好是这个后果）
翻译术语表不再参与识别 —— 那是给翻译用的。这里只认你显式填的、以及 Deepgram 那栏的 keyterms。

⚠️ 为什么默认关：一开启就会按上面那个地址发请求，没在本地跑服务的话， 每句都会打一次空请求。连续失败 2 次会自动暂停 30 秒，不会一直空转。
另外，如果流式识别本身就是本地 Whisper 分片，开了它相当于用同一个模型再听一遍， 收益很小，可以关掉。延迟模式（画面推迟）才用得上 —— 叠加模式手里没有留存的音频。

1.5 · 延迟画面画质

只在延迟模式下生效。延迟模式要把画面录下来再晚几秒播， 这中间视频会被重新编码一次 —— 码率给不够，画面一动就糊 （静止时帧间几乎没变化，很省；一运动编码器只能丢细节去凑码率）。

帧率这一项容易白丢一半。不显式给的话，Chrome 对标签页采集常只给 30fps —— 源本身是 60fps 时运动画面就发顿。它是上限不是强制值，源只有 30fps 时没有副作用。
⚠️ 但别填得太低。录制分片是 250ms 一片，帧率太低时一片里连一个关键帧都没有， 画面和声音会一起出不来（而字幕照常，看起来像"扩展坏了"）。 低于 12 会自动按 12 走，诊断面板里会说明。想不限制就填 0。
⚠️ 但帧率翻倍会让自动码率也跟着翻倍（保持同样的 bpp），编码压力也翻倍： 4K30 高画质 ≈ 64 Mbps，4K60 ≈ 128 Mbps。如果变卡，先把画质档位降一档。

档位是相对「标准档」的倍率，实际码率按你的画面尺寸算，所以换分辨率不用重调。 参考值（基准：1920×1080 ≈ 10 Mbps · 2560×1440 ≈ 17 · 3840×2160 ≈ 40）：
省资源 4K ≈ 20 Mbps · 标准 4K ≈ 40 · 高画质 4K ≈ 64 · 极致 4K ≈ 96。
衡量够不够的通用指标是 bpp（每像素每帧位数）：0.16 以下运动画面会糊， 0.26 左右干净，0.39 基本看不出二次压缩。H.264 效率低于 VP9/AV1，所以它需要更高码率。

2 · 翻译

使用 Google 翻译的公开免密通道，零配置。若所在网络无法访问，请改用其他服务。

DeepSeek 走的是 OpenAI 兼容协议，填法和 OpenAI 一样。 价格比 OpenAI 低不少，中文语感也好 —— 长时间挂着直播同传比较划算。 获取 API Key

本机跑的大模型：不需要 API Key、不联网、零成本。 前提是你已经在本机跑着 Ollama，并且拉过模型（ollama pull qwen2.5:7b）。
⚠️ 7B 级别在同传这种短句、口语、缺少上下文的场景下，质量不如云端服务 —— 它的价值是"完全离线、不看网络脸色"。机器够好可以换更大的模型。
